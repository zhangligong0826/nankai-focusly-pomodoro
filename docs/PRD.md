## 1. 产品目标（Product Goals）

1. **G1 - 提升专注力**：通过番茄工作法帮助用户进入深度专注状态，减少学习过程中的分心与中断。
2. **G2 - 任务可视化**：为用户提供统一的学习任务管理入口，避免任务遗漏、拖延，让"今天要做什么"一目了然。
3. **G3 - 行为可量化**：自动记录每日学习打卡与专注时长，让用户清晰看到周/月学习投入，形成正向反馈。
4. **G4 - 极致轻量化**：提供极简、无广告、打开即用的产品体验，避免第三方工具功能冗余带来的干扰。
5. **G5 - 数据可持久**：通过 LocalStorage 离线兜底 + Apifox Mock API 双层数据联动，确保用户数据不丢失、可恢复。

## 2. 用户故事（User Stories）

### 2.1 番茄专注计时模块

- **US-1.1** As a 研究生，我想要自定义学习时长和休息时长 so that 番茄钟能匹配我不同的学习节奏（如 25min 专注 + 5min 短休 + 4 轮后 15min 长休）。
- **US-1.2** As a 自习学生，我想要开始/暂停/结束/重置计时 so that 在临时中断（如去洗手间）时能灵活控制计时。
- **US-1.3** As a 用户，我想要专注结束后收到休息提醒、休息结束后收到再次专注提醒 so that 我不需要时刻盯着屏幕也能按节奏切换状态。

### 2.2 学习任务清单模块

- **US-2.1** As a 学生，我想要随时添加学习任务（含标题、备注、关联番茄数）so that 我能把待办清晰记录下来。
- **US-2.2** As a 用户，我想要对任务进行编辑、删除、完成标记 so that 任务状态能与我的实际进度保持同步。
- **US-2.3** As a 用户，我想要在开始番茄时绑定一个任务 so that 计时结束后专注时长能归属到对应任务上，便于后续复盘。

### 2.3 每日学习打卡模块

- **US-3.1** As a 用户，我想要完成一次番茄后自动打卡 so that 我不需要手动记录就能累积学习天数。
- **US-3.2** As a 用户，我想要同一天内重复打卡时只算一次 so that 打卡数据真实反映"今天学了没有"，避免刷数据。
- **US-3.3** As a 用户，我想要查看今日是否已打卡 so that 进入应用就能看到今日学习状态。

### 2.4 数据可视化统计看板模块

- **US-4.1** As a 用户，我想要查看本周每日专注时长 so that 我能直观看到本周学习投入的分布。
- **US-4.2** As a 用户，我想要查看本月每日专注时长 so that 我能复盘整月的学习节奏与趋势。
- **US-4.3** As a 用户，我想要查看累计专注时长、累计番茄数、累计打卡天数等汇总指标 so that 我能看到长期学习成果。

## 4. 功能详述（Functional Specification）

### 4.1 模块一：番茄专注计时模块

#### 4.1.1 计时器配置
- **入口**：首页右上角「设置」按钮
- **可配置项**：
  - 专注时长：1-120 分钟，默认 25
  - 短休时长：1-30 分钟，默认 5
  - 长休时长：1-60 分钟，默认 15
  - 长休间隔轮数：2-8 轮，默认 4
  - 声音提醒开关、桌面通知开关
- **存储**：调用 `PUT /api/timer/config`，并同步写入 LocalStorage
- **交互**：保存后立即生效，下次启动沿用

#### 4.1.2 计时控制
- **状态机**：`空闲 → 专注中 → 暂停中 → 专注完成 → 短休中 → 短休完成 → ... → 长休中 → 循环`
- **按钮区**：
  - 空闲：显示「开始」
  - 计时中：显示「暂停」「重置」「跳过」
  - 暂停：显示「继续」「重置」
- **计时显示**：大字号 MM:SS 倒计时 + 环形进度条
- **页面标题**：`<剩余时间> | Focusly` 格式

#### 4.1.3 完成与提醒
- **触发条件**：倒计时归零
- **提醒方式**：
  1. 浏览器 Notification API（需用户授权）
  2. 系统提示音（短促"叮"声）
  3. 页面内 Toast 弹窗
- **后续动作**：
  - 专注完成 → 自动进入短休；累计满 N 轮进入长休
  - 自动调用 `POST /api/checkin` 触发打卡
  - 自动调用 `PATCH /api/tasks/:id` 更新任务已消耗番茄数

### 4.2 模块二：学习任务清单模块

#### 4.2.1 任务数据结构
```ts
interface Task {
  id: string;              // UUID
  title: string;           // 任务标题（必填，≤50字）
  note?: string;           // 备注（可选，≤200字）
  status: 'todo' | 'doing' | 'done';  // 状态
  plannedPomodoros: number; // 计划番茄数
  completedPomodoros: number; // 已消耗番茄数
  createdAt: number;       // 创建时间戳
  updatedAt: number;       // 更新时间戳
  finishedAt?: number;     // 完成时间戳
}
```

#### 4.2.2 任务操作
- **新增**：点击「+ 新建任务」→ 弹窗输入 → 保存
- **编辑**：任务行点击「编辑」图标 → 弹窗修改 → 保存
- **删除**：任务行点击「删除」→ 二次确认（"确定删除此任务？"）→ 确认
- **完成切换**：任务行点击复选框 → 状态切换
- **绑定到当前番茄**：在番茄开始前下拉选择"当前任务"

#### 4.2.3 列表展示
- **默认排序**：未完成优先 → 创建时间倒序
- **筛选器**：全部 / 待办 / 进行中 / 已完成
- **空状态**：插画 + "还没有任务，点击 + 新建第一个吧"

### 4.3 模块三：每日学习打卡模块

#### 4.3.1 打卡数据结构
```ts
interface Checkin {
  date: string;      // YYYY-MM-DD（自然日）
  firstCheckinAt: number;  // 首次打卡时间戳
  pomodoroCount: number;   // 当日完成番茄数
  totalMinutes: number;    // 当日总专注分钟数
}
```

#### 4.3.2 打卡规则
- 每次完成一个专注番茄 → 调用 `POST /api/checkin`
- 后端按 `date` 去重：同一天首次打卡创建记录，后续只累加 `pomodoroCount` 和 `totalMinutes`
- LocalStorage 兜底：使用 `Set<date>` 存储已打卡日期，用于前端判断

#### 4.3.3 展示
- 首页顶部「今日打卡」卡片：大对勾 + "今日已专注 N 个番茄，M 分钟"
- 未打卡：灰色对勾 + "今天还没有开始专注哦"

### 4.4 模块四：数据可视化统计看板模块

#### 4.4.1 页面布局
```
┌─────────────────────────────────────┐
│  [累计时长]  [累计番茄]  [累计打卡]  │
├─────────────────────────────────────┤
│  切换：[本周] [本月]                 │
│                                     │
│     ECharts 柱状图                   │
│     (每日专注分钟数)                  │
├─────────────────────────────────────┤
│  任务完成 Top 5 / 分类占比（饼图）    │
└─────────────────────────────────────┘
```

#### 4.4.2 接口
- `GET /api/stats/weekly?weekStart=YYYY-MM-DD` → 返回本周 7 天数据
- `GET /api/stats/monthly?month=YYYY-MM` → 返回本月 30/31 天数据
- `GET /api/stats/summary` → 返回累计指标

#### 4.4.3 图表组件
- 柱状图：ECharts bar，X 轴日期、Y 轴分钟数，hover 显示详情
- 卡片：累计时长（小时:分钟）、累计番茄（个）、累计打卡（天）、连续打卡（天）

## 5. UI/UX 要求

### 5.1 整体风格
- **主色调**：番茄红 `#E74C3C` + 简约白 `#FFFFFF` + 辅助灰 `#F5F5F5`
- **强调色**：成功绿 `#2ECC71`、警告橙 `#F39C12`
- **字体**：系统默认无衬线（PingFang SC / SF Pro / Roboto）
- **风格关键词**：极简、扁平、留白、无广告、无多余装饰

### 5.2 信息架构（IA）
```
┌─ 顶部 Header ─ Logo | 今日打卡 | 设置
├─ 左侧 Tab Bar（PC 端）─ 计时 | 任务 | 统计
├─ 主内容区
└─ 底部（移动端 Tab Bar）
```

- **PC（≥1024px）**：左侧固定导航 + 右侧内容
- **移动端（≤768px）**：底部 3 Tab 切换，单列布局

### 5.3 交互细节
- 所有按钮 hover 有轻微缩放或颜色变化反馈
- 计时器圆形进度条采用 SVG 动画
- 任务完成动画：平滑淡出 + 划线
- 数据图表加载显示骨架屏
- 表单提交后自动关闭弹窗 + Toast 成功提示
- 错误输入（如空标题、负数时长）→ 输入框红边 + 提示文字

### 5.4 响应式适配
| 断点 | 设备 | 布局 |
|------|------|------|
| ≥1024px | PC / 平板横屏 | 左侧导航 + 主区，宽度自适应 |
| 768-1023px | 平板竖屏 | 顶部导航 + 主区 |
| ≤767px | 手机 | 底部 Tab + 单列布局，按钮可点区域 ≥44px |

### 5.5 可访问性
- 所有交互元素支持键盘操作（Tab / Enter / Esc）
- 文字与背景对比度 ≥ 4.5:1
- 关键操作（删除）有二次确认

## 7. 附录

### 7.1 非功能性需求（来自需求文档 §6）
- **性能**：计时无卡顿、无时间漂移；接口请求高效稳定，异步数据渲染无卡顿、无错乱
- **稳定性**：异常容错机制完善；定时器无叠加、无内存泄漏；接口超时/失败/重复请求拦截；LocalStorage 兜底读写安全
- **可拓展性**：模块化、组件化拆分清晰；支持后续云端存储、用户登录、数据导出、周报生成；数据结构通用，支持新增统计维度
- **可维护性**：命名规范、注释完整、层级清晰；功能单一职责、模块解耦；适配 AI 辅助开发

### 7.2 技术栈（来自需求文档 §7）
- 基础阶段：HTML5 + CSS3 + 原生 JavaScript
- 框架阶段：Vue 3（Composition API）
- 网络请求：Axios（封装通用请求工具类）
- 可视化组件：ECharts
- 数据：Apifox 模拟 RESTful + LocalStorage 离线兜底
- AI 辅助编程

### 7.3 交付标准（来自需求文档 §8）
- 完整可运行前端源码
- 规范化、带注释的代码文件
- 响应式适配完成的成品页面
- 支持打包部署上线的工程化项目（可选）
