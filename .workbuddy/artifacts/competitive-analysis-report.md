# Focusly 番茄时钟 · 竞品分析与改进方向报告

> 调研日期：2026-08-21
> 方法：现状盘点（基于全量代码审阅）+ 竞品联网调研（国内外主流番茄钟/专注类产品）+ 开源项目调研（GitHub 高 star 番茄钟/时间管理项目）
> 目标：为后续迭代计划提供可落地的优先级清单

## 一、项目现状盘点

### 1.1 核心功能（已具备，功能完整度较高）

| 模块 | 能力 |
|------|------|
| 番茄计时 | 专注/短休/长休三模式、自定义时长、开始/暂停/继续/重置/跳过、自动循环、声音+桌面通知+弹窗三重提醒 |
| 任务管理 | 增删改查、三态切换、分类标签、优先级色条、日期分组、绑定番茄 |
| 打卡体系 | 完成番茄自动打卡、连续打卡 Streak、里程碑文案 |
| 数据统计 | 周/月柱状图、分类占比饼图、4 张累计指标卡 |
| 附加 | 白噪音、专注锁定、每日目标庆祝、JSON/CSV 导出导入、深色模式、PWA |

### 1.2 技术栈与架构

- **技术栈**：Vue3 + Pinia + Vite + Vue Router(hash) + ECharts + Axios + vite-plugin-mock + vite-plugin-pwa
- **架构亮点**：
  - API 层「接口优先 + LocalStorage 兜底」的离线写入策略
  - 设计系统 token 化（CSS 变量 + 语义色 + 间距/字号/圆角/阴影完整，WCAG AA 达标）
  - 无障碍基础扎实（Skip Link、弹窗焦点陷阱、aria-live、focus-visible、reduced-motion）
  - 纯逻辑抽离（`exportCore.js`/`utils`）便于测试，node --test 43 用例
  - 分包策略（vendor + echarts 懒加载 + 路由 chunk）

### 1.3 明确短板（改进方向的事实基础）

1. **计时引擎不可靠**：`setInterval` 每秒递减 `remainingSeconds`，标签页后台节流/休眠会漂移，刷新即丢进度（已核实 `stores/timer.js:137`）
2. **无用户体系与云端同步**：数据全存 localStorage，换设备即丢
3. **无真实后端**：Mock 数据演示态
4. **无社交/游戏化**：无好友、排行榜、成就、养成物
5. **通知单一**：仅 Web Notification，锁屏/离页后依赖浏览器后台定时器
6. **视觉偏「工具实用」**：缺情绪价值与品牌记忆点

## 二、竞品分析（国内外主流产品）

### 2.1 重点深挖产品

**Forest 专注森林 —— 游戏化 + 损失厌恶标杆**
- 专注即「种树」，离开即枯萎（损失厌恶）；多人一起种树（任一人放弃全组树死）；金币解锁稀有树种；金币可兑换**真实植树**（与 Trees for the Future 合作，已种 200 万+ 棵）
- 可借鉴：把「专注锁定」升级为可视化养成物 + 损失厌恶 + 连续打卡解锁稀有主题

**Focusmate —— 社会监督（Body Doubling）**
- 陌生人 1v1 视频配对同屏静音工作，开场互报目标、结束复盘；免费每周 3 次
- 可借鉴：轻量「匿名自习室/陪学」模式，用「有人看着」驱动打卡

**番茄ToDo —— 学霸模式 + 自习室 + 数据复盘**
- 学霸模式（强制锁机+白名单）、番茄自习室（好友比拼）、待办集三模式、白噪音+海报背景
- 数据：热力图、高效时段、打断原因分析、成就徽章
- 可借鉴：统计从「记录」升级为「洞察」（热力图+高效时段+打断复盘）；锁机分级

**潮汐 Tide —— 氛围营造审美天花板**
- 专注/睡眠/冥想一体化；高质量自然声音景 + 音乐融合播放；每日日帖金句、分享卡片；极简低饱和配色
- 可借鉴：白噪音场景化 + 可混音 + 每日金句卡片；视觉走低饱和极简

**pomofocus.io —— 极简 + 任务估时减法设计**
- 打开即计时（无注册墙）；任务+预计番茄数→预估完成时间；日报/周/月/年报告
- 可借鉴：保留「零摩擦开始」路径 + 任务估时联动计时

### 2.2 其余产品速览

- **Flipd**：不可撤销锁机 + 公开承诺/排行榜/金钱惩罚（偏惩罚性）
- **Session**：开始前强制写意图、结束反思打分；自动勿扰/屏蔽/改状态（意图+复盘闭环）
- **Be Focused / Flat Tomato**：轻量工具型，Flat Tomato 主打扁平设计+可混音
- **专注清单**：任务+计时+报表一体，专注森林趣味种树
- **滴答清单**：番茄钟作为大而全清单的一环，证明「番茄钟服务任务闭环」是强需求

### 2.3 共性趋势（8 个反复出现的模式）

1. **养成/可视化成果**：Forest 种树 → 把抽象时长转成可收藏实体
2. **损失厌恶 > 正向奖励**：树会死、离开即失败、不可撤销锁机
3. **社会监督/共学**：视频陪学、一起种树、自习室
4. **锁机/屏蔽分级**：学霸模式、白名单、Full/Partial Lock
5. **氛围/声音场景化**：白噪音+可混音+日帖
6. **数据复盘深化**：热力图、高效时段、打断原因、周/月报
7. **意图设定 + 复盘闭环**：开始写意图、结束反思
8. **任务与番茄强绑定**：预计番茄数、预估完成时间、分类占比

### 3.1 代表性项目

| 项目 | 定位/量级 | 可借鉴的工程实践 |

| **pomofocus**（社区重构版） | Web 番茄钟标杆，`Jsmond2016/PomoFocus` 为 Vue3+Vite5+Pinia+TS+Vitest（与 Focusly 同栈） | 任务按「预估番茄数」建模；日/周/月三级统计聚合；CSV 导出 |

| **Pomatez** | 4.2k★，React+Electron+Tauri 双后端 | Connector 模式抽象平台能力；显式计时器状态机；托盘进度、全局快捷键 |

### 3.2 共性工程模式（8 条，标注 Focusly 现状）

1. **绝对截止时间计时** `remaining = max(0, deadlineAt - Date.now())`，不靠 setInterval 递减，防标签页节流漂移 —— **缺失（最高优先级）**
2. **刷新恢复 + 多标签收敛**：持久化 deadline/阶段/暂停态，Web Locks API 防重复结算 —— **缺失**
3. **存储分层**：设置/任务→localStorage，历史/打卡→IndexedDB —— **部分具备**
4. **计时器状态机**：focus/shortBreak/longBreak 枚举 + 4 轮长休 —— **已具备**
5. **PWA**：manifest + SW 预缓存 + 通知 tag 去重 + SW 通知降级 —— **声明具备，通知去重未做**
6. **Web Audio 单 AudioContext**：白噪音/铃声共用上下文 + 手势解锁 autoplay —— **具备白噪音，手势解锁未做**
7. **统计可视化 + 导出**：日/周/月聚合 + CSV —— **已具备**
8. **测试金字塔**：Vitest 测纯函数 + Playwright E2E —— **缺失**

## 四、改进方向（按优先级排序）

### 🔴 P0 —— 正确性与可靠性（工程地基，先打牢）

**P0-1 计时器改 deadline 模式 + 刷新恢复**
- **改进内容**：将 `setInterval` 递减改为「绝对截止时间」计时（`deadlineAt` 存 localStorage），页面刷新/后台节流/休眠后按 `Date.now()` 重新计算剩余时间；持久化当前阶段/暂停态/绑定任务，重启自动恢复
- **预期收益**：修复核心计时漂移 bug（后台标签页 setInterval 会被节流至每分钟甚至暂停），刷新不丢进度——这是番茄钟产品的基本盘正确性
- **实施成本**：中（改 `stores/timer.js` 核心逻辑 + `utils/timer.js` + 恢复逻辑，约 2-3 天）

**P0-2 存储分层：引入 IndexedDB**
- **改进内容**：设置/任务/当前状态继续用 localStorage，历史会话/打卡记录迁入 IndexedDB（用 `idb-keyval` 或原生封装），突破 5MB 上限
- **预期收益**：长期使用数据不丢、统计不因空间不足失效，为后续「更多历史维度」打底
- **实施成本**：中（新增存储抽象层 + 迁移，约 2 天）

### 🟠 P1 —— 产品差异化（对标竞品趋势，建立记忆点）

**P1-1 可视化养成物（虚拟花园/森林）**
- **改进内容**：专注时长兑换「植株成长」，连续打卡解锁稀有品种，中途放弃（专注锁定触发）导致植株枯萎（损失厌恶）；主页/统计页可视化
- **预期收益**：补齐最被验证的情绪价值机制（Forest 验证了 200 万真实植树），显著提升留存与分享意愿
- **实施成本**：高（需养成物素材 + 成长状态机，约 1-2 周）

**P1-2 数据复盘深化（热力图 + 高效时段）**
- **改进内容**：在周/月柱状图基础上，新增日历热力图（GitHub 风格）、高效时段识别、打断原因记录
- **预期收益**：统计从「记录」升级为「洞察」，增强复访动机（番茄ToDo 核心亮点）
- **实施成本**：中（ECharts 已有基础，热力图组件 + 聚合逻辑，约 3-5 天）

**P1-3 白噪音场景化 + 每日金句**
- **改进内容**：声音场景化（雨/海浪/森林/咖啡可混音）、专注开始前每日金句卡片
- **预期收益**：对标潮汐的氛围营造，让声音成为第二张名片
- **实施成本**：中低（现有白噪音模块扩展，约 2-3 天）

**P1-4 锁机分级（学霸模式）**
- **改进内容**：在现有「专注锁定」基础上，增加强锁（离开即失败+枯萎）、白名单、定时锁机（防熬夜）
- **预期收益**：把「专注锁定」从软提醒升级为可选的强自律工具，覆盖更硬核用户
- **实施成本**：中（沿用 useFocusLock 基础，约 3 天）

**P1-5 意图设定 + 结束反思闭环**
- **改进内容**：专注开始前可选填写「本次目标」，结束时弹反思打分（Session 模式）
- **预期收益**：让每次专注有目的性，提升「有效专注」感知，差异化显著
- **实施成本**：低（表单 + 存储 + 弹窗，约 1-2 天）

**P1-6 任务估时 + 番茄绑定强化**
- **改进内容**：任务建模增加「预估番茄数→预估完成时间」，计时页实时显示「今日预计完成」；分类占比联动
- **预期收益**：对齐 pomofocus 的「任务服务计时」核心，让任务管理真正驱动计时
- **实施成本**：低（现有 plannedPomodoros 字段已具备，补 UI 联动，约 1-2 天）

### 🟢 P2 —— 增长与长期（社交/同步/工程债）

**P2-1 轻社交自习室**
- **改进内容**：匿名「陪学」模式（头像+目标文字，非视频），好友专注时长榜
- **预期收益**：补齐外部监督机制（Focusmate/番茄ToDo 验证），社交传播获客
- **实施成本**：高（需后端/实时通道，约 2 周+）

**P2-2 用户体系 + 云端同步**
- **改进内容**：登录 + 云端数据同步（对齐 README 已知 P2 路线图）
- **预期收益**：解决换设备丢数据，是 P2-1 社交的前提
- **实施成本**：高（后端 + 鉴权 + 同步冲突处理）

**P2-3 测试金字塔补齐**
- **改进内容**：引入 Vitest 补计时/统计纯函数单测，Playwright 补核心流程 E2E
- **预期收益**：P0-1 计时器重构的回归保障，长期迭代安全网
- **实施成本**：中（搭建 + 用例，约 3-5 天）

**P2-4 通知去重 + SW 降级通道**
- **改进内容**：通知 tag 去重，Service Worker 通知降级（锁屏仍可收到）
- **预期收益**：提醒可靠性提升，减少重复打扰
- **实施成本**：低（约 1-2 天）

## 五、结论与建议路线

**核心判断**：Focusly 功能完整度在同类中属中上，工程基础扎实（设计系统、无障碍、离线兜底、测试意识）。当前最大风险不在「缺功能」，而在「计时正确性」——P0-1 的 setInterval 计时是基本盘 bug，应优先修复。

**建议分三步走**：

1. **第一步（本周）**：P0-1 计时器 deadline 化 + P0-2 IndexedDB 分层 —— 打牢地基
2. **第二步（2-4 周）**：P1-1 养成物 + P1-2 热力图复盘 + P1-5 意图复盘 —— 建立差异化记忆点（三者分别是竞品验证最充分、洞察价值最高、成本最低）
3. **第三步（长期）**：P2-2 云同步 → P2-1 轻社交 → 其余按需

**一句话总结**：先把「倒计时数得准、刷新不丢」这个 1 分基本功做扎实，再用「养成物 + 数据洞察」这两个被市场反复验证的 9 分机制做出差异化，最后才谈社交与云端。
